01

From download to first page

Start with the included bilingual demo. All commands below run from the project root. You need PHP 8.1 or newer with JSON support; the basic example needs no external API.

  1. Check your PHP version

    Download or clone the project into any directory, then open a terminal there.

    Terminal
    php --version

    Live JSON refresh also needs the PHP cURL extension and a working CA trust store.

  2. Validate and package the demo

    Validation checks configuration and rendering. The example builder adds its JavaScript assets and packages the runtime.

    Terminal
    php bin/seo.php validate examples/basic/site.php
php tools/build-example.php

  3. Start the development server

    Terminal
    php -S 127.0.0.1:8088 -t examples/basic/dist tools/router.php

    Open http://127.0.0.1:8088/en or /ar. Use View Page Source to see the initial content, canonical URL, language alternates and JSON-LD. Open /sitemap.xml to see the four public, localized URLs.

✓
Try it without JavaScript

Disable JavaScript and reload. The initial response still includes readable public content. Re-enable it to see the demo SPA take over.

02

Add it to your SPA

The framework works with built HTML and assets. Your frontend build system and visual design stay yours. Keep a clean entry template outside the generated deployment output.

Suggested project layoutFILES
seo-framework/
├── bin/seo.php
├── bootstrap.php
├── src/
├── assets/
├── site.php                 # Your site configuration
├── public/index.html        # Clean SPA entry template
└── dist/                    # Existing frontend build + packaged runtime

1. Prepare the clean template

Match rootId to your SPA’s mount element. An empty element works, or put <!-- SEO:BODY --> inside it. Put the optional head marker inside <head>. Preserve your real built script and stylesheet URLs.

public/index.htmlHTML
<!doctype html>
<html lang="en">
<head>
  <meta charset="utf-8">
  <meta name="viewport" content="width=device-width, initial-scale=1">
  <title>My Website</title>
  <!-- SEO:HEAD -->
  <script type="module" src="/assets/app.js"></script>
</head>
<body>
  <div id="app"><!-- SEO:BODY --></div>
</body>
</html>

2. Create a site configuration

Save this as site.php at the project root. Change the HTTPS origin and text to match your site.

site.phpPHP
<?php
declare(strict_types=1);

return [
    'siteUrl' => 'https://example.com',
    'siteName' => 'My Website',
    'template' => 'public/index.html',
    'rootId' => 'app',
    'languages' => ['en'],
    'defaultLanguage' => 'en',
    'prefixLanguages' => false,
    'spaRoutes' => ['/account', '/login'],

            'path' => '/',

                    ],
                ],
            ],
        ],
    ],
];

3. Package after your frontend build

Your frontend build must already have created dist/ and its assets. Packaging adds PHP, metadata, public HTML snapshots and rewrite rules.

Terminal
php bin/seo.php validate site.php
php bin/seo.php build site.php dist

Upload the complete dist/ directory, including dotfiles, to a PHP-capable web root. Repeat packaging after every frontend build.

!
Plan the handoff for hydrated apps

The fallback is generic semantic HTML. Apps that hydrate framework-generated markup need an intentional fallback handoff or a separate mount strategy. Keep the fallback’s public content consistent with the SPA.

Page fields

Translation fields include title, nav, description, image, sections and structuredData. A section supports a heading, text (a paragraph or list), items and links with url and label.

Page-level fields include schemaType, ogType, lastModified (YYYY-MM-DD) and navigation: false. Hiding a page from navigation keeps it in the sitemap. Paths accept ASCII letters, numbers, hyphens, underscores and slashes.

05

Turn public data into pages

A source fetches JSON. An adapter maps records to page definitions. The same runtime can serve products, courses, articles, services or pricing.

Define the source

Add these options to a working site config. Replace the placeholder endpoint before enabling live refresh.

Inside site.phpPHP
'seed' => 'seed.json',
'sources' => [
    'products' => [
        'url' => 'https://api.example.com/public/products',
        'dataPath' => 'data.items',
        'type' => 'list',
        'allowEmpty' => true,
    ],
],
'includeFiles' => ['adapters/products.php'],
'pageProvider' => require __DIR__ . '/adapters/products.php',

dataPath selects a nested response value using dot notation. Set type to list or object. Use allowEmpty: false if an empty response must be treated as a failed refresh.

Map records to public pages

adapters/products.phpPHP
<?php
declare(strict_types=1);

return static function (array $data, array $site): array {
    $pages = [];
    foreach ($data['products'] ?? [] as $product) {
        if (!is_array($product)
            || !preg_match('/^[a-z0-9-]+$/D', $product['slug'] ?? '')
            || !is_string($product['name'] ?? null)) {
            throw new RuntimeException('Invalid public product.');
        }
        $pages[] = [
            'path' => '/products/' . $product['slug'],
            'translations' => [
                $site['defaultLanguage'] => [
                    'title' => $product['name'],
                    'description' => $product['description'] ?? '',
                ],
            ],
        ];
    }
    return $pages;
};

Supply an initial snapshot

The seed contains the extracted data map, not the original API response envelope. This example matches the adapter immediately above.

seed.jsonJSON
{
  "generatedAt": 0,
  "data": {
    "products": [
      {
        "slug": "desk-lamp",
        "name": "Desk lamp",
        "description": "An adjustable lamp for your workspace."
      }
    ]
  }
}

Use --offline to package the seed without fetching. A zero timestamp makes it stale, so the running PHP application attempts a refresh. Offline packaging does not disable later runtime refreshes.

i
Only public, anonymous data

Requests use HTTPS, verify TLS, send no user cookies or authentication headers, refuse redirects, and enforce an eight-second timeout and four-MB limit per source. Configure pagination yourself. Never use request parameters as source URLs.

Use validateData to reject incomplete datasets before caching. Dynamic route validation also runs before a snapshot is replaced. Deleted records disappear from pages and the sitemap after the next successful refresh.

06

Keep metadata in step

The first response comes from PHP. After your SPA router changes a public route, call the optional browser helper to update metadata without reloading.

Your SPA router hookJAVASCRIPT
import { updateSeo, markPrivate } from '/__seo/seo-client.mjs';

// After navigating to a public page:
updateSeo({
  title: 'About our studio | My Website',
  description: 'A small team building useful tools.',
  canonical: 'https://example.com/en/about',
  language: 'en',
  direction: 'ltr',
  alternates: {
    en: 'https://example.com/en/about',
    ar: 'https://example.com/ar/about',
    'x-default': 'https://example.com/en/about',
  },
});

// After navigating to an account or login route:
markPrivate();

updateSeo() updates the document title, language, direction, canonical link, language alternates, social metadata and JSON-LD. Pass image and structuredData when needed; the default schema is a generic WebPage.

For subdirectory hosting, include your base path in the helper import, canonical URLs, alternate URLs, frontend asset paths and SPA router configuration.

07

Fresh data. A reliable fallback.

The first request after the snapshot TTL attempts a refresh. A nonblocking writer lock lets concurrent visitors keep using the previous snapshot. A complete, valid dataset replaces the cache through an atomic rename.

01Reuse

Serve a fresh snapshot.

02Refresh

Fetch and validate after TTL.

03Recover

On error, retain the last good data.

The defaults are a 3,600-second TTL and 300-second retry backoff. An error keeps the previous snapshot or bundled seed. Upstream API caching may add its own delay.

From the project root
php bin/seo.php refresh site.php
php bin/seo.php status site.php
From your deployed build directory
php seo.php refresh
php seo.php status

refresh forces one refresh and exits nonzero on failure or lock contention. status is read-only. Running packaged seo.php without arguments also refreshes. There is no public HTTP force-refresh endpoint.

Choose storage on the deployment host

Packaged deployments reset the source-side cacheDirectory. By default, they use a config-specific system temp directory on the target host. Set SEO_CACHE_DIRECTORY to an absolute, writable private directory outside the web root for persistent storage. Configure the same value for web PHP and cron/CLI.

Schedule a refresh

On a Unix PHP host, add a cron command every 15 minutes. Replace the directory placeholder with your deployed path and use your host’s PHP 8.1+ CLI executable.

Cron · every 15 minutes
*/15 * * * * cd "YOUR_DEPLOYMENT_DIRECTORY" && php seo.php refresh

HTML responses use Cache-Control: private, no-store. Inspect X-SEO-Generated-At, X-SEO-Cache and X-SEO-Refresh; a successful CLI result or advancing timestamp confirms refresh.

Before you go live

  • Set your real HTTPS siteUrl and any hosting basePath.
  • Build into a staging directory and package after the frontend build.
  • Upload the full output, including both .htaccess files.
  • Use package-relative imports and bundle adapter PHP/JSON files.
  • Verify a public page, a private route, an unknown route and the sitemap.
  • Confirm /.seo/config.php returns HTTP 403 and missing assets return 404.
  • Run php seo.php status and, for real API sources, php seo.php refresh.

Web server support

Apache 2.4 or LiteSpeed: enable rewrite support and .htaccess overrides. Existing custom policies are protected; review and merge your rules. Use --replace-htaccess only when you intend to replace the existing policy.

Nginx: provide equivalent rules that deny the private directory, return real 404s for missing assets and send public routes to PHP-FPM through seo.php while preserving the original request URI.

Deploy new hashed assets before new entry points and keep older assets for clients still using them. Your hosting process owns activation and rollback.

11

When something needs a closer look

Public routes return 404 on the server

Check that your full build, including the root .htaccess, was uploaded. Apache/LiteSpeed needs rewrite support and overrides enabled. Nginx needs equivalent PHP fallback rules. Confirm language prefixes and any basePath match the requested URL.

Validation says the template cannot be found

template resolves relative to your config file. Keep a clean entry HTML file at that location. Avoid using a previously rendered output as the template, and ensure rootId matches the mount element.

The build refuses to replace .htaccess

The builder protects existing custom rules. Review and merge your redirects, security and PHP settings. If replacing that file is intentional, pass --replace-htaccess to the build command.

Public API refresh fails or content looks old

Run php seo.php refresh in the deployed directory and inspect its error and timestamp. Verify the source URL, extracted dataPath, PHP cURL support, outbound connectivity, writable cache storage and adapter validation. A failed refresh deliberately preserves the previous content.

cURL reports an issuer-certificate error

Configure the host’s PHP CA trust store. For CLI, set curl.cainfo in the active php.ini to a maintained CA bundle. CLI and web PHP may use different configurations. Keep TLS verification enabled.

The JavaScript app shows different content

The semantic fallback and the SPA are separate renderers. Keep their public content aligned and call updateSeo() after client-side navigation. Hydrated apps need a planned handoff from the generic fallback.

Can I host the PHP application on GitHub Pages?

GitHub Pages serves the static documentation in docs/. Run the application’s PHP gateway on a PHP-capable host to get dynamic routes, cache refreshes and runtime metadata. This repository’s generated PHP package needs that server runtime.

Give these docs a home

This entire documentation website lives in docs/. It is plain HTML, CSS and JavaScript with relative asset URLs, so it works at a repository subpath or a custom domain. There are no external fonts, scripts or build dependencies.

  1. Commit and push the docs/ directory to your GitHub repository, including docs/.nojekyll.
  2. Open the repository’s Settings → Pages.
  3. Under Build and deployment, choose Deploy from a branch.
  4. Select the branch containing these files, choose /docs as the folder, then save.
  5. Wait for the Pages deployment to finish. Open the URL shown in the repository’s Pages settings.

These steps follow GitHub’s publishing-source guide ↗. Choose the branch you actually use; no specific repository name or account is baked into the site.

Preview or edit the site

From the project root
php -S 127.0.0.1:8090 -t docs

Open http://127.0.0.1:8090. Edit docs/index.html for content, docs/assets/styles.css for appearance, and docs/assets/docs.js for search and interactions. Push changes to the selected branch to update the published docs.
